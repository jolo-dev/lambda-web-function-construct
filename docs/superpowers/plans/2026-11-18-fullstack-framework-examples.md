> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Demonstrate production Next.js, Nuxt, and TanStack Start servers on Lambda Web Functions with preserved deployable artifacts and optional CloudFront/private-S3 static delivery.

**Architecture:** Keep existing single-entry bundling; introduce an exclusive prebuilt-directory mode that preserves a Node.js 24 deployment tree. Put CloudFront, browser assets and the scoped Web Function origin policy in a separate optional delivery construct. Three version-pinned example stacks exercise the same deployment contract and retain framework-specific build/launch logic outside the library.

**Tech Stack:** TypeScript, JSII, Bun test/build, AWS CDK 2.274, Lambda Web Functions Node.js 24 Linux Arm64, CloudFront OAC/Functions, S3, framework-specific Node production servers, Docker for reproducible builds.

## File map

- `src/web-function.ts`: maintain public Web Function resource/props, validate mutually exclusive modes, publish endpoint ARN/auth/endpoint type, preserve current revision/endpoint graph. Avoid embedding directory traversal or CloudFront details here.
- `src/web-function-artifact.ts`: private staging, symlink validation, bounded ZIP creation and deterministic archive content; return package path and selected entrypoint. A single entry point for packaging lets both modes share upload logic without changing legacy semantics.
- `src/web-function-delivery.ts`: public optional delivery construct and JSII-compatible asset mapping/options. Own CloudFront, S3 and IAM resource policy; do not put framework build logic here.
- `src/index.ts`: re-export public interfaces and delivery construct.
- `test/web-function-artifact.test.ts`, `test/web-function-delivery.test.ts`: isolated archive tests and synthesis tests; keep `test/web-function.test.ts` regression baseline.
- `examples/fullstack/shared/build-arm64.sh`, `examples/fullstack/shared/probe.ts`, `examples/fullstack/shared/README.md`: reproducible build and bounded smoke-test support, not a generalized framework plugin.
- `examples/fullstack/{nextjs,nuxt,tanstack-start}/`: each owns `package.json`, a lockfile, application source, `build-artifact` script, `index` launcher, CDK stack and README. Determine exact filenames after inspecting each pinned production build; do not guess them in the library.
- `examples/package.json`, root `package.json`, `README.md`: add only scripts/docs needed to run and test examples.

## Notes for implementers

- S3 code bucket is *not* the asset bucket. Source archive is uploaded as ZIP with `extract:false`; static tree is uploaded as ordinary S3 objects.
- CloudFront OAC for Web Functions uses `always-amz-auth` and `lambda:InvokeWebFunctionEndpoint`; do not use Lambda Function URL methods/signing or assume `ApplicationManaged` enforces a Web Function resource policy.
- The Web Function default startup is root `index.js`; `AWS_LAMBDA_NODEJS_ENTRYPOINT` must be package-relative. Its provided listen address is reserved; read it, do not set it in revision environment.
- Asset readiness precedes revision reachability without introducing a distribution→revision→distribution dependency cycle. Fetch an old asset through a **previously uncached URL at the old key** after updating to distinguish S3 retention from an edge cache hit.
- Error responses and signed-in responses also belong to the zero-shared-cache tests. A successful synth is not a successful Web Function startup or CloudFront policy acceptance.
